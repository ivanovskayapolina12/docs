Webhooks serve as the core **real-time notification mechanism** for your financial integration. Instead of making repetitive API requests (polling) to check payment states, compliance verifications, or dispute status, Pagsmile pushes signed HTTP POST requests directly to your backend as soon as events occur.

## Event Families

Pagsmile categorizes webhooks into three primary domain families:

<CardGroup cols={1}>
  <Card title="Pix Transactions" icon="money-bill-transfer" href="/webhooks/transactions">
    Financial settlement notifications for inbound/outbound payments and refunds (`PIX_PAYMENT_IN`, `PIX_PAYMENT_OUT`, `PIX_REFUND_IN`, `PIX_REFUND_OUT`) 

    **Scope:** `ACCOUNT` or `USER`
  </Card>

  <Card title="KYB Compliance" icon="user-shield" href="/webhooks/kyb">
    Status updates for compliance sessions on Virtual and Master accounts (`VA_ACCOUNT_KYB`, `MASTER_ACCOUNT_KYB`).

     **Scope:**  `PLATFORM` (Master) / `USER` (Virtual)
  </Card>

  <Card title="MED Processing" icon="sensor-alert" href="/webhooks/med">
    Lifecycle events for Special Refund Mechanisms (`MED_CASE_*`, `INFRACTION_*`). 

    **Scope:** `USER` or `ACCOUNT`
  </Card>
</CardGroup>

## Webhook Provisioning

Where and how to configure your subscriptions depend on the event family:

<Tabs>
  <Tab title="Management API (/v3/webhooks)">
    Programmatically subscribe to transaction and KYB events using numeric IDs[cite: 1]:

    - `1` — `PIX_PAYMENT_IN`[cite: 1]
    - `2` — `PIX_PAYMENT_OUT`[cite: 1]
    - `3` — `PIX_REFUND_IN`[cite: 1]
    - `4` — `PIX_REFUND_OUT`[cite: 1]
    - `5` — `VA_ACCOUNT_KYB`[cite: 1]
    - `6` — `MASTER_ACCOUNT_KYB`[cite: 1]
  </Tab>
  <Tab title="Merchant Dashboard (MED)">
    <Warning>
      The `/v3/webhooks` API does **not** support MED processing events.
    </Warning>

    Configure MED and Infraction notifications via **Merchant Dashboard**:

    1. Go to **API Keys > Webhooks > Add Webhook**.
    2. Select **MED PROCESSING** for cases or **INFRACTION PROCESSING** for infractions.
  </Tab>
</Tabs>

## Receiver Checklist

<Steps>
  <Step title="Expose a Stable URL">
    Use a permanent HTTPS endpoint. **Do not rely on HTTP redirects.**
  </Step>
  <Step title="Capture Raw Bytes">
    Read and retain the exact raw request body in memory before parsing JSON for signature verification.
  </Step>
  <Step title="Validate Headers">
    Verify both `X-Content-Hash` and `X-Signature` before processing the JSON payload.
  </Step>
  <Step title="Enforce Idempotency">
    Persist the event using its documented idempotency key (`delivery_id` or `txn_id` + event type).
  </Step>
  <Step title="Acknowledge Fast">
    Return an explicit `HTTP 200` status code immediately upon accepting the payload.
  </Step>
</Steps>
