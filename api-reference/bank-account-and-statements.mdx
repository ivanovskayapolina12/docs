This collection of endpoints enables client applications to retrieve account status, monitor balances, and fetch transaction history.

> All monetary values (e.g., `balance`, `amount`, `frozen_amount`) are returned as **JSON strings**. Always use fixed-point decimal arithmetic (or arbitrary-precision libraries) to process these values—never parse them directly into floating-point numbers.

![Bank Statements](/images/bank_statements.jpeg "Bank Statements")

### Endpoints Summary

**Get Bank Account:** Inspect real-time account state, available/frozen balances, registered webhooks, and active PIX keys.

**Get Statements:** Fetch transaction entries (credits/debits), payment metadata, and cursor tokens for pagination.

## Error Reference

Common error causes across all endpoints:

- Missing, expired, or malformed authentication headers (`X-Signature`, `X-Timestamp`, `X-Nonce`).
- Replayed nonces or invalid content hashes.
- Insufficient permissions or unmapped downstream service errors.

| **HTTP Code** | **Error Code / Reason** | **Description** |
| :-- | :-- | :-- |
| `400` | Bad Request / Invalid Headers | Missing or mismatched target headers (`X-ISPB`, `X-Account-Number`). |
| `401` | Unauthorized | Signature mismatch or expired timestamp. |
| `500` | Missing Client Context | Client identity could not be verified internally. |
| `501` | Account RPC Failure | Downstream account provider communication error. |
| `4004010` | Nil Account | Target account does not exist or is inaccessible. |
