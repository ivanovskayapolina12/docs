This reference documents the JSON shapes shared across the 40 Open API v3 routes in this Space.

### Runtime JSON rules

* The service serializes generated Go structs with Sonic, not protobuf JSON. Enum fields are native JSON numbers.
* Integer timestamp fields are JSON numbers. Explicit onboarding, webhook, and MED lifecycle timestamps use Unix milliseconds. Preserve other integer time fields without guessing a unit unless the endpoint states one.
* Monetary values—amounts, fees, balances, frozen amounts, limits, and MED amounts—are decimal strings. Use decimal arithmetic.
* Generated zero values can appear as `0`, `""`, `false`, `null`, or `[]` when a mapper does not populate a declared field.
* Optional request fields are presence-aware. Omitting a field differs from sending `0`, `false`, or `""`.
* Unknown JSON members are not rejected in strict mode today. Send only documented fields and do not rely on unknown-field acceptance.

### Shared objects

* **`TxnParty`** — `name`, `document_id`, numeric `document_type`, `bank_account`, numeric `bank_account_type`, `bank_branch`, `bank_code`, `bank_name`
* **`TxnDetails`** — parties; transaction/settlement/merchant IDs; numeric `txn_status` and `source_type`; decimal-string amount/fees; currency, memo, rejection reason; integer time fields; PIX/TED details; original settlement ID
* **Statement item** — IDs, decimal-string amount, memo, numeric created time/payment/status/type fields, `is_credit`, parties, and parent transaction references
* **`AccountReferenceV3`** — `ispb`, `account_number`
* **Bank account** — identifiers; decimal-string balances; currency; `pix_keys`, `limit_config`, `webhooks`, `fee_configs`
* **Onboarding account** — reference and holder data, status/compliance status, session ID, trading name, notification email, millisecond lifecycle timestamps, and account reference; managed accounts add numeric model and optional linked account
* **`WebhookInfo`** — `webhook_id`, string `event_type`, `callback_url`, numeric `status`, numeric lifecycle times, account/subscription IDs, suspend reason
* **Pagination** — numeric `page`, `page_size`, `total`, `total_pages`; statement cursor has numeric `timestamp`, string `id`, numeric `direction`
* **MED models** — stable IDs, numeric canonical status, display text, decimal-string amounts, millisecond lifecycle/deadline values, original transaction/parties, timeline, infraction and refund projections

Party document IDs can be masked according to merchant configuration. A missing or `null` generated object means the current mapper did not populate it; it is not proof that the field can never appear.

### Intentional string exceptions

* `MasterAccountInfo.document_type` and `ManagedAccountInfo.document_type` are `"CPF"` or `"CNPJ"`, unlike numeric request/compliance and party document-type fields.
* Webhook create requests and create responses use numeric event types. `WebhookInfo.event_type` in get/list/update responses is a string: `PIX_PAYMENT_IN`, `PIX_PAYMENT_OUT`, `PIX_REFUND_IN`, `PIX_REFUND_OUT`, `VA_ACCOUNT_KYB`, or `MASTER_ACCOUNT_KYB`.
* Every fee-config field is a string, including `fee_kind`.
* MED `status_display` and infraction `freeze_status` are human-facing strings. Use adjacent numeric status fields for program logic.

Dynamic QR request `expires` is a duration in seconds and defaults to 7200; it is not an epoch timestamp.
