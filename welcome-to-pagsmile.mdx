### **Pagsmile overview**

Pagsmile Open API integrates account and payment services into your systems. You can use the API to create managed accounts, query bank account information, manage Pix keys, and initiate payments and refunds. You can track the results through query endpoints and event notifications.

Operations use POST requests, JSON request bodies, and AK/SK signature authentication. Account permissions depend on the credential type, account ownership, and target account.

### **Intended audience**

Open API is designed for businesses and platforms that manage accounts, collections, payments, and transaction results in their own systems. You can manage your own Master Account and, when authorized, create VA or PA accounts for other entities and manage their account details and transactions separately.

Onboarding, account fund operations, and event subscriptions use different authorization scopes. Configure the credentials required for each capability before integrating.

How accounts relate to payment features:

- After account opening, confirm the account's compliance status and bank account readiness. Then use the account services and payment capabilities that have been enabled.
- Use the target account's authorization context for incoming payments, outgoing payments, and account queries. Account ownership does not mean balances are automatically aggregated.
- Pix refunds link to the original incoming payment transaction. MED cases must also link to the original Pix transaction. Each must meet its own conditions. Connecting lines indicate relationships between operations, not call sequence or cardinality.
- Webhooks notify you of changes based on the subscribed event types and scopes. Use them with detail, status, and statement entry queries to confirm processing results. MED callbacks are limited to the scope that has been enabled and delivered.

      <td>Operating account that reuses its parent MA's approved compliance records</td>

    <tr>
      <td>VA</td>
      <td>Managed account that must belong to a parent MA and has its own compliance records and bank account</td>
    </tr>
    <tr>
      <td>PA</td>
      <td>Payment account that must belong to a parent MA or a VA under that MA and has its own compliance records and bank account</td>
    </tr>
    <tr>
      <td>PLATFORM / USER / ACCOUNT</td>
      <td>Three API credential identities: platform, user, and account</td>
    </tr>
    <tr>
      <td>ISPB</td>
      <td>Bank participant identifier that identifies an account together with the account number</td>
    </tr>
    <tr>
      <td>Pix Key</td>
      <td>Identifier that points to a Pix payee account, distinct from API signing credentials</td>
    </tr>
    <tr>
      <td>EndToEnd ID</td>
      <td>Original Pix transaction ID, used to link transactions and for operations involving MED cases</td>
    </tr>
